# Seat preferences

Keep the table-assignment optimizer and its proven packing/hard-rule priorities. In Balanced/Fairness, prioritize avoiding unwanted table pairings, then maximize attendees with at least one preferred tablemate, before named-companion scores and clique rewards. Fairness mode additionally protects the minimum normalized table satisfaction after coverage and before names. Raw weighted mode gives names a fivefold base weight. Record preference source explicitly; infer old generated tag clauses only as migration compatibility. Duplicate requests collapse to the strongest effective request.

After choosing tables, refine exact chairs independently within each long table. In Balanced/Fairness, first maximize the number of attendees with at least one positive target in an opposite, same-side adjacent, or diagonal seat. Next minimize the block-shape penalty, then maximize weighted proximity and minimize distance cost. Being elsewhere at the same long table does not count as chair coverage. Raw weighted mode also prefers block shapes before chair proximity, but keeps its existing weighted table-assignment objective. Existing seat indices encode row=floor(index/2), side=index%2. Opposite seats score 4, adjacent on the same side 2, adjacent diagonals 1, farther seats 0. Ordered single-target named requests use weight × 5000 × (n − rank) / (n × (n + 1) / 2), rounded to integer points, where rank starts at zero and n is the requester’s distinct named-target count. Names therefore get descending shares of the same influence budget, while narrower lists remain stronger per match. Rebuilt chip clauses follow the visible name-chip order, followed by legacy mapped names. Duplicate targets retain their first position. ANY alternatives retain their existing best-match semantics and equal-list normalization; tags use weight × 1000 / distinct matching tag companions for that requester. Avoidance weights do not use the positive-list divisor. Thus single-target name requests get a fivefold base boost, and narrower lists receive stronger individual pairings. Repeated requests are deduplicated before counting targets. Negative preferences penalize proximity. ANY alternatives earn the best matching proximity, not a reward for each alternative. Every-target tag clauses expand through the existing domain resolver.

For positive, explicit single-person requests, count distinct requesters at the same table. When a person has at least two requesters, use the sum of weighted squared row distances to those requesters as a secondary cost to minimize. This pulls popular people toward their group’s weighted center, not the physical center of an otherwise empty table. Keep coverage, block shape, and proximity priorities ahead of centrality. Include weighted squared row distances between shared-tag companions in this final tie-breaker to pull otherwise equivalent group placements together. Use the existing normalized request weights so narrow requests retain their influence. Duplicate requests, avoidance, tags, and unselected alternatives do not create popularity. Exact enumeration and bounded swaps use the same objective order: nearby coverage in Balanced and Fairness, block shape in every mode, weighted proximity, then distance cost. Only claim a bound proof when coverage and proximity reach their upper bounds and both block cost and distance cost reach zero, or exhaustive enumeration finishes.

Spatial groups come from shared tags, maximal mutual named cliques, and a named companion with at least two incoming requesters. Duplicate member sets count once, using the strongest source weight. For each group represented by at least three people at a table, the block penalty counts rows beyond ceil(member count / 2), weighted by source and divided by group size. A four-person group therefore prefers two rows across both sides over four rows in one column. Odd groups may leave one boundary seat to another group. Conflicting or overlapping groups stay soft. This affects chair positions without adding chips or changing table assignments.

For each table with n assigned attendees, search only the first n seats, filling paired rows from the start of the table. Unused seats remain at the end; an odd attendee count leaves one free chair in the last occupied row. This is a structural restriction on automatic placement, so avoidance and proximity rewards cannot create gaps. Manual drag placement can still use any physical chair.

Enumerate permutations for tables with at most eight attendees. Larger groups seed one candidate by growing contiguous blocks along positive preference connections (including shared tags), retain attendee-order and shuffled alternatives, then use deterministic multi-start pair swaps with incremental scores and a shared deadline; keep the best valid incumbent. This refinement is exact only for enumerated fixed-table permutations and heuristic for large tables. Table optimality does not prove a globally optimal chair plan across alternate table arrangements.

Reserve part of the normal solve budget for chairs. Always produce complete, unique in-capacity seat indices and independently validate them. Table locks remain table locks; Arrange may move chairs within locked tables. Replace saved seatIndices with the produced plan. URL persistence already stores them.

Record one additional debug stage with its actual chair indices, covered-guest count, block cost, proximity score, and distance cost (lower is better). Its outcome explicitly distinguishes fixed-table enumeration from bounded local improvement. Debug replay must lay out those exact positions, and direct companion rows describe opposite/side/diagonal/far seating. Do not invent a global optimality claim for the refinement.

The table worker receives three quarters of the run budget, leaving the remaining shared deadline for chair refinement.
